# JD Portal — Bug Fixes & UX Polish, 23 Jul 2026

Fixes for the three issues found in first real user testing of the 22 Jul MFA-gated portal revamp (see `docs/todolist/todolist_23Jul2026.md` "New today" section). All three verified end-to-end per soul.md §3.1/§14 before being marked done.

## 1. Vertical scroll regression — fixed

**Root cause (confirmed, matched the self-diagnosis in the todolist):** two compounding issues, not just the one originally suspected.
- `.jd-portal` (`src/components/JDPortal/JDPortal.css`) lost `overflow-y: auto` when the fintech re-skin rewrote the rule.
- `.portal-shell` (`src/components/JDPortal/PortalShell.css`, new in the 22 Jul revamp) used `min-height: 100vh` instead of a bounded `height: 100vh`. Since `body` (`src/index.css`) is `height: 100vh; overflow: hidden`, an unbounded `.portal-shell` simply grew past the viewport and got clipped — restoring `overflow-y: auto` on `.jd-portal` alone would not have been sufficient, because none of its ancestors had a bounded height for that overflow to apply against.

**Fix:** `.portal-shell` → `height: 100vh; max-height: 100vh; overflow: hidden;` (bounds the flex column so `.portal-main`'s `flex: 1; min-height: 0` is a real constraint), plus `overflow-y: auto` restored on `.jd-portal`. This mirrors the existing pattern already used by the chat app shell (`src/App.css` `.app-container`/`.app`).

**Files:** `src/components/JDPortal/PortalShell.css`, `src/components/JDPortal/JDPortal.css` (backed up first: `.20260723_V1.bak`).

## 2. History modal → nested, single-open accordion — rebuilt

**Decisions confirmed with user before implementing:**
- Clicking a company row expands it in place to reveal its doc links; clicking a doc's "View" expands that doc's rendered content inline beneath the links (nested accordion, not expand-all).
- Single-open at both levels — opening a new company collapses the previous one (and any open doc); opening a new doc within the open company replaces the previously open doc.

**Implementation:**
- `src/components/JDPortal/JDHistoryList.jsx` rewritten: company header is now a `<button>` toggling `expandedCompany` state; each `.docx` entry's "View"/"Hide" button toggles `expandedDoc` (keyed `${companyKey}::${docType}`), rendered via a new `DocViewerInline` component nested directly under that company's doc-links row.
- **New component** `src/components/JDPortal/DocViewerInline.jsx` + `.css` — an inline, non-overlay rendering of the same mammoth-converted, DOMPurify-sanitized docx HTML the modal used.
- **`DocViewer.jsx` (the original modal) was left untouched** — it's still used by `JDRunPanel.jsx` for viewing a fresh run's results, which wasn't part of this bug report and wasn't verified as broken. Per soul.md's golden-rule spirit, a new component was branched instead of modifying a working, already-verified one out from under a different caller.
- New CSS in `JDPortal.css`: `.jd-history-card-header` (button reset + hover), `.jd-history-card-meta`, `.jd-history-chevron` (rotates on open), `.jd-history-card-body`, `.jd-match-score--inline`.

**Files:** `src/components/JDPortal/JDHistoryList.jsx` (backed up first: `.20260723_V1.bak`), `src/components/JDPortal/JDPortal.css`, new `DocViewerInline.jsx`/`.css`.
